# Instagram 中文按钮标签错配（.15）

用户报告 `.15` 中“每个按钮对应的中文都不对”，并要求解决不了时退回原先版本、保留“下载图标放在收藏左侧”。目标仍为 Instagram 451.0.0.53.80 / 385713073 / arm64-v8a。

## 资源边界回归

`.15` 将 `IgStr` 从解包应用的基础 Context 改成优先使用 `Utils.getActivity()`。这项改动缺少对宿主下载语言包的运行路径验证，是本次回退的内容。

原版451的直接字节码证据：

- `InstagramAppShell.getResources()` 可通过 `getOverridingResources()` 返回宿主资源包装器。
- 带 `DownloadedIgResources.getText` / `DownloadedIgResources.getString` 标记的实现把 `getText(I)` 交给宿主下载语言表查找。
- 该表的入口对编号高16位为 `0x7f130000` 的字符串先查询下载语言包，未命中后才读原始 Resources；动态资源名称查找得到有效编号，并不保证这个宿主编号查找会返回 Piko 的文字。
- 因而通用 Activity 的 `getString(id)` 不能直接作为扩展字符串资源的读取边界。仅检查编译资源表中的中文内容正确，无法覆盖此问题。

修复恢复 `.14` 的读取逻辑：从扩展初始化时的应用 Context 开始，循环解包 `ContextWrapper.getBaseContext()`，在基础包资源上按名称查找和读取 Piko 文字。保留原来的编号缓存和格式化行为，不再访问 Activity 的资源表。

`.15` 的左侧下载按钮、当前行媒体/轮播位置/Context桥接、87项中文补全与新版Android日志保存实现均保留。没有更改字体，也没有更改按钮对应的设置键、持久化值或点击行为。

## 针对性回归

`check-ig-string-context.py` 编译真实的 `IgStr.java`，在独立JVM中提供最小Context/Resources测试替身。应用和Activity包装器使用故意错配的宿主语言表，基础Context使用仓库中全部443项真实简体中文条目。这是对宿主资源边界的模拟，不是手机语言包或Android运行时的完整仿真。

- 使用 `.15` 的真实读取器时，443项标签全部被错误宿主表替换，检查失败。
- 恢复基础Context读取后，443项标签全部与各自资源名正确绑定，宿主表读取次数为零。
- 同时检查格式占位符、缺失资源回退，以及基础资源内容更新后的读取。
- 该检查已加入现有Instagram构建流程；原有377项测试继续执行。

最终安装包还须验证资源读取入口、443条中文资源和收藏前的下载按钮调用。手机上的实际按钮标签和语言切换仍需用户复验；没有启动或控制手机。此前首次切中文退出的根因仍未确诊，本修复不宣称解决了该退出问题。
